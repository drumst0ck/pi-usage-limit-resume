# CodexBar parity: usage-limit-resume for every provider that has reset times
Objective (rewritten at L7): the plugin ONLY saves each provider's reset time (5h/weekly/monthly, like CodexBar) and, when the exhausted limit resets, continues the task it was doing. It never chooses or switches orchestrator/worker/provider.
Branch: master in ~/Developer/GitHub/pi-usage-limit-resume (work-unit commits since L14). Delivery: https://github.com/drumst0ck/pi-usage-limit-resume (branch main, CI green on Node 22/24); npm not published (no npm login on this machine). Test runner: `npm test`; types: `npm run typecheck` (strict, against Pi 1.2.0 types).

## Specs
- S1: "hagamos que funcione con todos los providers que tiene codexBar"
- S2: "haz exactamente lo mismo que hace codexBar con todos los providers"
- S3 (scope decision by the assistant, user-visible): NOT implemented for safety: browser cookie import, Chromium "Safe Storage" decryption and macOS Keychain reads of other apps. Everything else CodexBar does with a plain credential file or an API key is in scope.
- S4: Never refresh or rewrite another tool's credential file (CodexBar does the same, refresh tokens rotate). Refuse files readable by group/others. Never log tokens or account ids.
- S5: Every usage source failure falls through silently to the next source and finally to the probe fallback; a lookup can never hold a user's message (bounded by timeouts).
- S6: Generic path for ALL CodexBar provider ids: `codexbar usage --provider <id> --json` when CodexBar is installed; opt-out `GENTLE_USAGE_LIMIT_CODEXBAR=0`.
- S7: Native (no CodexBar) sources for providers that expose reset timestamps through plain HTTP with a credential the user already has: gemini (`~/.gemini/oauth_creds.json`), zai, kimi, minimax (API key held by Pi).
- S8 (SUPERSEDED by S9 at L7): tiers/failover order. Removed.
- S9: "vamos a eliminar la parte de que este plugin elija orquestador y worker, eso lo haremos luego en otro plugin, este plugin solo debe guardar cuando es el reset de cada provider y seguir la tarea que estaba haciendo cuando se reinicie el limite agotado"
- S11: "esto me preocupa, debe de ser un plugin de pi, que se instale y sea completamente aparte de gentle pi y no se sobrescriba nunca"
- S10: "tenemos que dar servicio a la gente que usa cualquier provider para programar con pi" and "haz todo literalmente como lo hace codexBar": coverage is keyed by Pi provider id; every CodexBar provider that reports a reset over plain HTTP with a credential Pi or the provider's own CLI file already holds is implemented the way CodexBar does it. S3 still excludes cookies/keychain/Chromium decryption (re-confirmed with the user).
